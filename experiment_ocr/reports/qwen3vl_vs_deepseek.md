# Qwen3-VL (8B/4B) vs DeepSeek-OCR: парное сравнение OCR (2026-07-27)

Проверка гипотезы «одна VLM на всё» (OCR + саммаризация + ориентация-LoRA):
достаточно ли хороши Qwen3-VL-8B/4B-Instruct как OCR по сравнению со
специализированным DeepSeek-OCR.

**Дизайн:** те же 200 pdf_text из `docs_set.json` (эталон = fitz 1-й страницы,
рендер 300 dpi, даунскейл до 1600 px, greedy decoding, max 4096 токенов).
Движки: `engines/oc_qwen3vl.py` (8B), `engines/oc_qwen3vl4b.py` (4B),
transformers 4.57.6, bf16, прогон 2×GPU (`phase_o1b_qwen3vl.py`, шард 60/40).
Для 4B добавлен `repetition_penalty=1.15` (см. ниже раздел про 4B).

**ВАЖНО — чувствительность к промпту.** Промпт в стиле nanonets («extract text,
tables in html») заставляет Qwen3-VL извлекать ТОЛЬКО таблицу, пропуская шапку
и тело письма (F1 0.36/0.77 на docs 161468/49811). Промпт v2 («Transcribe the
entire document… include ALL elements: letterheads, organization names, dates…»)
исправляет: те же документы → F1 0.974/0.997. Все результаты ниже — с промптом v2.

**Парное сравнение:** qwen3vl лучше на 123 документах (62%), deepseek — на 35

подмены (билайн→билин 8x); систематических подмен кириллицы нет (26 смешанных
токенов, как у deepseek). Цифры и реквизиты читает заметно лучше (потери 16.5%
против 25.4%).

## Катастрофические сбои — режим отказа РАЗНЫЙ

- **qwen3vl (2 док., F1=0.00):** бланки Proforma_Invoice_2BM — галлюцинационный
  цикл HTML/SVG: генерация base64-картинки в `<img src="data:image/svg+xml;base64,…">`
  до упора в max tokens (272 с), текст документа не выдан. Ловится тривиальным
  фильтром покрытия (cov 2.7 > 1.5).
- **deepseek (1 док., F1=0.28):** repetition-loop на счёте (cov 1.4).

Repetition-loop в целом чаще у qwen3vl (11 vs 2 документов cov>1.5) — в проде
обязателен фильтр покрытия + (опционально) repetition_penalty в generation config.

## Qwen3-VL-4B: проверка «золотой середины» (2026-07-27)

**Грабля 4B — HTML/imgur-галлюцинация.** Без repetition_penalty 4B на бланках
впадает в цикл `<img src="https://i.imgur.com/…">` до max tokens (doc 161468:
F1=0.00, 234 с). Промпт «не выводи image tags» НЕ помогает;
**repetition_penalty=1.15 полностью лечит** (F1=0.966, на нормальных документах
качество не меняется). Прогон ниже — с rep-penalty (8B прогнан без него;
у 8B rep-penalty, вероятно, тоже сократил бы число лупов 11→? — не проверено).

**Парный анализ qwen3vl4b vs deepseek (n=200): статистическая ничья** —
delta F1 mean −0.0002 / med 0.0000, win 40% / tie 14% / loss 46%.

| Метрика | qwen3vl4b | deepseek |
|---|---|---|
| Слов-ошибок на документ (med / p90) | 5 / 42 | 6 / 43 |
| Документов F1 ≥0.95 | 89 | 96 |
| Средний F1 на 20 худших | 0.492 | 0.549 |
| Выдумано шумовых слов (Σ) | 2983 | 1775 |
| Смешанная кириллица+латиница | 103 | 33 |
| Repetition-loop (cov>1.5) | 8 (с rep-penalty!) | 2 |
| Цифровые токены потеряно | 23.9% | 25.4% |
| Скорость, с/стр med | 14.6 | **4.6** |

**qwen3vl4b vs qwen3vl-8B: 8B выигрывает 68% документов** (delta +0.031),
ошибок на документ med 2 vs 5, цифры 16.5% vs 23.9%, документов F1≥0.95:
149 vs 89. Качество в семействе Qwen3-VL круто растёт с размером:
4B даёт ровно 3B-класс (DeepSeek/Nanonets), а не середину между 3B и 8B.

## DeepSeek-OCR-2 (2026-07-27): апгрейд НЕ состоялся

DeepSeek-OCR-2 (релиз 27.01.2026, энкодер Visual Causal Flow, динамическое
разрешение (0-6)×768²+1024², тот же 3B MoE-класс) прогнан на том же наборе
(`engines/oc_deepseek2.py`, дефолтный конфиг model card: base 1024, tiles 768 —
другие base_size ломают кастомный код энкодера, см. ниже).

**Парный анализ deepseek2 vs deepseek-v1 (n=200): v1 лучше** —
win 32% / tie 22% / loss 45%, delta F1 mean −0.0135.

| Метрика | deepseek2 | deepseek-v1 |
|---|---|---|
| BoW-F1 mean / med | 0.887 / 0.948 | **0.901** / 0.944 |
| Слов-ошибок на документ (med / p90) | 5 / **59** | 6 / 43 |
| Документов F1 ≥0.95 / 0.50–0.80 | 97 / 31 | 96 / **19** |
| Средний F1 на 20 худших | 0.498 | 0.549 |
| Выдумано шумовых слов (Σ) | **3982** | 1775 |
| Смешанная кириллица+латиница | **147** | 33 |
| Repetition-loop (cov>1.5) | 6 | 2 |
| Цифровые токены потеряно | **22.9%** | 25.4% |
| Скорость, с/стр med | 6.3 | **4.6** |

Характерные регрессии v2 на RU-документах: (1) **markdown-мусор** — топ-замены
это «всего→\*\*всего», «пао→\*\*пао», «руб.→руб.\*\*» (модель стилизована под
markdown сильнее v1, шумовых слов в 2.2 раза больше); (2) **посимвольные ошибки
кириллицы** — «Толстобров→Толстодроб», «сети→селу», украинская «І», mixed-script
в 4.5 раза больше; (3) тяжелее хвост (p90 ошибок 59 vs 43) и больше лупов.
Плюсы v2: цифры (22.9% vs 25.4%) и медиана F1 чуть выше (0.948 vs 0.944).
EN-бенчмарки (olmOCR-bench 76.3 vs 75.7) на RU-корпус не переносятся.

**Грабля:** base_size ≠ 1024 ломает кастомный deepencoderv2
(`UnboundLocalError: param_img`, deepencoderv2.py:445) — разрешение входа у
OCR-2 жёстко зашито под base 1024 + тайлы 768.

## Точка отсчёта качества: ABBYY FineReader 16 (2026-07-27)

ABBYY FineReader PDF 16 — классический эталон распознавания на кириллице.
Использована **исключительно как точка отсчёта качества** (не как кандидат):
прогнана на том же наборе 200 документов через Hot Folder (задача
`ocr_experiment`, Run once, Russian and English, Text UTF-8;
движок-обёртка `phase_o1c_finereader.py`).

**Парный анализ finereader vs deepseek (n=200): мёртвая ничья** —
win 40% / tie 18% / loss 42%, delta F1 mean −0.003.

| Метрика | finereader | deepseek |
|---|---|---|
| BoW-F1 mean / med | 0.898 / **0.949** | 0.901 / 0.944 |
| 3gram-cos | **0.932** | 0.919 |
| Слов-ошибок на документ (med / p90) | 8 / **34** | 6 / 43 |
| Пропущено слов эталона (Σ) | **1889** | 3019 |
| Выдумано шумовых слов (Σ) | 2452 | **1775** |
| Смешанная кириллица+латиница | **9** | 33 |
| Цифровые токены потеряно | **18.8%** | 25.4% |
| Катастрофические сбои | **0** | 1 (repetition-loop) |
| Скорость | **1.3 с/стр, CPU** | 4.6 с/стр, GPU |

Сильные стороны FR: лучшая полнота извлечения (меньше всех пропусков слов),
самый чистый текст (9 смешанных токенов), цифры точнее DeepSeek, нулевые

Характерные ошибки: регистровые подмены на стилизованных гарнитурах
(«сотовой→сотобой», «в→б/6», «базовая→базобая»), пунктуация (–→-, «0→01»).
Против qwen3vl-8B проигрывает ожидаемо (loss 55%, −0.034). Калибровочный
вывод: эталон подтверждает уровень DeepSeek-OCR (паритет), Qwen3-VL-8B
эталон превосходит.

## Gemma-4-E4B-it (2026-07-27): конкурентом не является

google/gemma-4-E4B-it (релиз 03.2026, ~7.6B dense, transformers 5.14.1,
venv_gemma, движок `engines/oc_gemma4.py`, промпт v2) прогнан на том же
наборе (шард 2×GPU, `phase_o1b_qwen3vl.py --engine gemma4`).

**Парный анализ gemma4 vs deepseek (n=200): deepseek лучше по всему** —
loss 55% vs win 32%, delta F1 mean −0.022.

| Метрика | gemma4 | deepseek |
|---|---|---|
| BoW-F1 mean / med | 0.879 / 0.922 | **0.901 / 0.944** |
| Документов F1 ≥0.95 | 62 | **96** |
| Пропущено слов эталона (Σ) | 4070 | **3019** |
| Выдумано шумовых слов (Σ) | 3305 | **1775** |
| Цифровые токены потеряно | 30.2% | **25.4%** |
| Repetition-loop (cov>1.5) | 10 | **2** |
| Слов-ошибок на документ p90 | 70 | **43** |
| Скорость, с/стр med | 21.4 | **4.6** |

Характерные ошибки gemma4: цифры («0→01», 30.2% потерь — худший результат
среди VLM), удвоение согласных («россети→россетти», «брендированного→

Единственный плюс — чистый plain-text вывод без галлюцинаций-катастроф
(на sanity-документах), но по совокупности (качество ниже deepseek, в 4.7
раза медленнее, лупы 10 vs 2) в шорт-лист не входит. Заметка: 12B/26B-A4B/
31B варианты gemma-4 не помещаются в 24 GB VRAM без квантизации.

## Вывод

**Qwen3-VL-8B — лучшее качество OCR из всех протестированных движков**
(BoW-F1 0.931/0.979; 75% документов с F1≥0.95 против 48% у deepseek; в 3 раза
меньше слов-ошибок на типичном документе: медиана 2 vs 6; цифры 16.5% vs 25.4%).

**Qwen3-VL-4B «золотой серединой» НЕ является:** качество — в точности
3B-класс DeepSeek/Nanonets (0.900), но в 3 раза медленнее DeepSeek (14.6 vs
4.6 с/стр: 4B dense против MoE с ~570M активных), чаще зацикливается (8 vs 2
даже с rep-penalty) и больше шумит (mixed-script 103 vs 33). При равном
качестве DeepSeek-OCR остаётся лучшим выбором 3B-класса.

Цена:
1. **Скорость:** медиана 17 с/стр против 4.6 у deepseek (≈3.7×; mean раздут
   зацикливаниями). Частично компенсируется vLLM-инференсом (не тестировался).
2. **Робастность:** repetition-loop в 5.5 раз чаще (11 vs 2) — фильтр покрытия
   обязателен; отловленные документы → fallback на deepseek/nanonets.
3. **Устойчивость к повороту не тестировалась.** Косвенные основания для
   оптимизма: энкодер SigLIP-2 (в экспериментах по ориентации 100% на классе
   180°) и устойчивость nanonets/Qwen2.5-VL к 90° (0.78). Тест `phase_o3` на
   qwen3vl — следующий шаг.

**DeepSeek-OCR-2 апгрейда не даёт** (см. раздел выше): на RU-корпусе чуть хуже
v1 по качеству, в 2.2 раза больше шума, в 4.5 раза больше подмен кириллицы,
медленнее на 37%. В 3B-классе остаётся **DeepSeek-OCR v1**.

**Для схемы «одна VLM на всё» (OCR + саммаризация + ориентация-LoRA) —
жизнеспособно:** OCR-качество выше специализированного deepseek, а LoRA
ориентации (99.83%) уже обучена именно на Qwen3-VL. Альтернатива — двухмодельная
схема: deepseek (быстрый основной OCR) + Qwen3-VL (саммаризация, ориентация-fallback,
OCR-fallback по фильтру покрытия).

Файлы: движки `engines/oc_qwen3vl.py` (8B) / `oc_qwen3vl4b.py` (4B,
rep-penalty 1.15) / `oc_deepseek2.py` (DeepSeek-OCR-2), прогон `phase_o1b_qwen3vl.py`
(`--engine qwen3vl|qwen3vl4b`), результаты в `results/o1_results.jsonl`
(бэкап v1-промпта 8B: `o1_results.jsonl.bak_qwen3vl_v1`),
сводка `reports/ocr_compare.md`.
