# Публикация на Habr

## Файлы

- `article.md` — тело статьи в Markdown. Вставляется в редактор Habr как есть
  (Habr сам конвертирует Markdown в свой HTML). `<cut/>` уже на месте.
- `img/fig1_tri_proverki.png` — схема «три проверки» (в шапке)
- `img/fig2_slope_pravilo.png` — слоуп-график перестановки (вторая проверка)
- `img/fig3_recall_po_tipam.png` — гантели recall по типам (раздел про дообучение)

Все PNG отрендерены в 2× (≈2080 px по ширине), светлая тема, шрифты статьи.

## Порядок

1. Новая публикация → тип **«Аналитика»** (или «Кейс»).
2. Заголовок: **Рейтинг, который не устоял: как три проверки обнулили сравнение эмбеддингов**
   (короткий вариант — «Рейтинг, который не устоял»).
3. Переключить редактор в режим Markdown, вставить содержимое `article.md`.
4. Заменить три плейсхолдера картинок. Для каждого: поставить курсор на строку
   `![...](IMG_figN_...)`, удалить её, через кнопку «Изображение» загрузить
   соответствующий PNG из `img/` — Habr сам подставит `<img src="https://habrastorage.org/...">`.
   Строку с курсивом под картинкой (подпись) оставить.
5. КДПВ (обложка) — можно взять `fig1_tri_proverki.png`.
6. Хабы: **Машинное обучение**, **Natural Language Processing**, **Data Mining**.
   Если доступен — **Учебный процесс в IT** не подходит; вместо него **Читальный зал** опционально.
7. Теги: `эмбеддинги, классификация документов, ЭДО, методология экспериментов,
   утечка данных, метрики, LoRA, t-SNE, giga-embeddings, воспроизводимость`
8. Проверить перед публикацией:
   - таблицы отрисовались (Habr понимает GFM-таблицы);
   - блоки `> **Проверка ...**` показаны как цитаты;
   - код в обратных кавычках (`giga_480m` и т.п.) — моноширинный, не ломает строку;
   - `<cut/>` разбил статью на анонс и тело.

## Если Markdown-режим недоступен / глючит

Вставить как обычный текст и вручную:
- `##` / `###` → заголовки h2/h3 кнопками панели;
- `> ...` блоки → «Цитата»;
- `**жирный**`, `_курсив_` → кнопками;
- таблицы — через вставку таблицы, скопировать значения;
- картинки — как в п. 4.
