## Анализ проблем

### 1. Модель предсказывает только 0°
Модель возвращает "0" для всех файлов, независимо от истинной ориентации. Это означает, что модель не способна определять ориентацию документов через vision API.

### 2. Сервер упал после 1811 файлов
llama-server crashed после обработки ~1811 файлов, возможно из-за:
- Нехватки памяти (модель 21 GB + vision processing)
- Утечки памяти в llama-server
- Проблем с vision processing pipeline

### 3. Неправильное использование модели
Qwen3.5-35B-A3B-Uncensored-HauhauCS-Aggressive - это **текстовая reasoning модель**, а не vision модель. mmproj файл может быть несовместим или не предназначен для определения ориентации документов.

## Выводы

1. **Qwen3.5-35B через llama.cpp не подходит** для определения ориентации документов
2. **Модель не способна** определять ориентацию через vision API (предсказывает только 0°)
3. **ViT-Large 384 остаётся лучшим выбором** (99.63% accuracy)
4. **Для vision задач** нужны специализированные модели (ViT, EfficientNet, PaddleOCR)

## Рекомендации

### Для production
Использовать **Ensemble ViT + PaddleOCR** (99.80% accuracy)

### Альтернативы
- ViT-Large 384 (99.63%)
- EfficientNet-B1 (99.57%)
- PaddleOCR (99.00%)

### Почему Qwen3.5 не работает
- Это текстовая reasoning модель, не vision модель
- Не обучена на задаче определения ориентации
- mmproj файл несовместим или не работает правильно
- Требует специализированной fine-tuning для vision задач
