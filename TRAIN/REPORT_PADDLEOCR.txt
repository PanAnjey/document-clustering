# Отчёт: Эксперимент с PaddleOCR

## Дата: 2026-07-01
## Модель: PP-LCNet_x1_0_doc_ori (PaddleOCR)

---

## Описание эксперимента

PaddleOCR содержит отдельную модель **PP-LCNet_x1_0_doc_ori** для классификации ориентации документов (0°, 90°, 180°, 270°).

### Установка

```bash
py -m pip install paddlepaddle paddleocr
```

### Использование

```python
import os
os.environ['FLAGS_use_mkldnn'] = '0'      # отключение oneDNN (баг на Windows)
os.environ['FLAGS_use_onednn'] = '0'

from paddlex import create_model

model = create_model(model_name='PP-LCNet_x1_0_doc_ori')
result = model.predict(str(img_path))

for r in result:
    angle = int(r['label_names'][0])   # '0', '90', '180', '270'
    score = float(r['scores'][0])      # уверенность 0-1
```

### Нюансы

- **oneDNN баг на Windows**: PaddlePaddle 3.3.1 + oneDNN вызывает `NotImplementedError` при инференсе. Решение — отключить через `FLAGS_use_mkldnn=0`
- **CPU only**: модель работает на CPU (GPU-версия для CUDA 13.2 не установлена)
- **Скорость**: ~79мс/файл (2991 файл за 237s)

## Выводы

1. **PaddleOCR** — хороший метод (99.00%), но уступает ViT-Large (99.63%)
2. **Принципиально другой подход** — анализ текста/документа vs визуальные паттерны
3. **Взаимодополняемость** — ошибки не коррелируют, что позволяет улучшить результат через ансамбль
4. **Ensemble ViT + PaddleOCR** — оптимальный выбор для production (99.80%)
